Daily Digital

A browser-based digital community skills simulator for occupational therapy education, practice, and functional cognition observation.

Admin-led sessions Patient alias login Learn / Practice / Assessment / Free Report-card records
Purpose

What Daily Digital is for

For patients

Practise everyday digital tasks in a safe Android-like simulation without using real sensitive apps.

  • Messages, Calendar, WhatsApp, Maps, and Bank simulations.
  • Tasks range from guided learning to independent assessment.
  • No real patient identifiers are required in the app.
For OT/admin users

Observe functional performance and cognitive process indicators during realistic community tasks.

  • Monitor live interfaces for up to 6 joined devices.
  • Push app-specific modules or multi-app scenarios.
  • Review objective progress by alias over time.
Roles

Two entry points

1Admin opens `/admin`Create or manage a current session, select users, and push tasks.
2User opens `/`Log in using assigned alias and 4-digit PIN.
3User joins sessionEnter the 6-letter session PIN shown by admin.
4Admin observesMonitor live screen state, prompt if needed, and review records later.

Current limitation: multi-browser/device sync requires the Cloudflare backend integration. The deployed backend foundation exists, but the React app still needs to be wired to it.

Modes

What each mode is for

LearnTeach one app function at a time. Highlights correct targets and checks simple outputs.
PracticeScenario-based rehearsal. Checklist can be visible, skipped, or hidden for memory attempt.
AssessmentIndependent performance. Task card is minimal; prompts are admin-triggered and recorded.
FreeUnstructured exploration. Users can open apps and try functions without task framing.
Important

After selecting a mode, press the admin `ENTER` button to confirm. Practice and Assessment scenarios should start from the Home screen.

Learn mode

How to use Learn mode

Admin steps
  1. Select joined user from the live panel.
  2. Select `Learn` and press `ENTER`.
  3. Choose a Learn module: Home, Messages, Calendar, WhatsApp, Maps, or Bank.
  4. Observe whether the user clicks the target or answers correctly.
What is tracked
  • Modules completed.
  • Time spent on each module.
  • Percentage of accurate clicks/answers overall and by app.

Learn mode is for teaching app functions, not testing deconfliction or independent problem-solving.

Practice mode

Practice mode uses page-aware support

1Push scenarioAdmin chooses a single-app, two-app, or multi-app scenario.
2Checklist shownUser sees only the checklist for the current page/app.
3Correct actions progressChecklist row turns green automatically when the correct action is detected.
4Try from memoryUser can repeat without checklist and request prompts if needed.
Clinical use

Practice is ideal for grading down support: visible checklist first, then hidden checklist with prompts, then Assessment when ready.

Assessment mode

Assessment is independent-first

User side
  • Starts from Home screen.
  • One task card appears at a time.
  • Instructions are hidden unless user presses `Show task`.
  • Answer checks appear only when the information is available.
  • Submit requires confirmation to avoid accidental ending.
Admin side
  • Can push graded prompts that are recorded.
  • Gets stuck alert after more than 30 seconds without progress.
  • Can review completed checklist steps and cognitive metrics.
  • Ending an assessment does not end the whole session.
Scenarios

Scenario examples

Single appRead Doctor appointment in Messages. Add appointment in Calendar. Plan route in Maps. Check bank balance and payment details.
Two appsRead SMS then save to Calendar. Check Calendar then plan route in Maps. Reply in WhatsApp then add dinner to Calendar.
Multi-appClinic day: read SMS, save in Calendar, plan route. Social and clinic: save appointment, then reply to dinner message.

Practice and Assessment scenarios should be selected based on the patient’s current goal, not just app difficulty.

Privacy

Recommended safety practices

Do
  • Use aliases only inside the app.
  • Keep patient-to-alias mapping offline.
  • Use the app for simulation, not real banking or messaging.
  • Review records as functional trends, not isolated pass/fail scores.
Do not
  • Enter names, NRIC, phone numbers, or real appointment identifiers.
  • Expose API keys in frontend environment variables for production.
  • Use multi-device sessions clinically until backend sync is connected.
  • Assume prompts equal independence; record prompt level carefully.

Quick reference

Daily session checklist

  1. Open `/admin` and confirm the session PIN.
  2. Have user log in with alias and 4-digit PIN.
  3. User enters 6-letter session PIN.
  4. Select user card in admin live panel.
  5. Choose mode and press `ENTER`.
  6. Push Learn module, Practice scenario, or Assessment scenario.
  7. Observe live view and prompt only when clinically appropriate.
  8. Review Past Sessions for objective progress trends.
